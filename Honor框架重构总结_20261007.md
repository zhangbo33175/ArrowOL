## 1. 新增封装（对齐 HonorUI「自动注销监听 + 统一绑定 + 统一生命周期」风格）

> 参考 HonorUI

> **只增不改**
> 方式落地，未照搬参考实现。

### 1.1 `LuaBehaviourSuper:AddGlobalEvent(key, callback)`（新增）



* 位置：`Singleton/HonorBases/LuaBehaviours/None/LuaBehaviourSuper.lua.txt`

* 语义：`handler(self, callback)` 包装回调 → `HonorEventHelper:AddListener(key, h)` → 句柄记录进 `_globalEventListenerList`。

* 自动注销：OnDestroy 中 `HonorEventHelper:RemoveListenerByTarget(self)` 按 target 统一移除（无需手动配对注销）；记录表用于统一管理并释放引用。

* 用法示例：



```
function MyView:OnAddListeners()
    self:AddGlobalEvent(EventCmd.RoleLevelUp, function(...) self:OnRoleLevelUp(...) end)
end
```

### 1.2 `LuaBehaviourSuper:AddUpdateTimer(delay, func, isRealTime)`（新增）



* 位置：同上文件。

* 语义：启动循环协程（`HonorCoroutineHelper:Start(handler(self, ...))` 内 `while true` + `WaitForSeconds/WaitForSecondsRealtime`），间隔 `delay` 秒执行 `func`；协程句柄记录进 `_timerList` 并返回（可提前手动 `HonorCoroutineHelper:Stop(co)`）。

* 自动注销：OnDestroy 遍历 `_timerList` 逐一 `HonorCoroutineHelper:Stop(co)`（StopByGO 仍按 GO 兜底）。

* 说明：未采用 `HonorTimerHelper:RegisterDeltaTime`（其需 procedure 参数、按事件名派发，与 "实例级循环回调" 语义不符）。

### 1.3 统一注销链路（OnDestroy，顺序未变）

`UnloadAllAssets()` → `HonorEventHelper:RemoveListenerByTarget(self)` → `HonorCoroutineHelper:StopByGO(go)` → `_timerList` 遍历 Stop（新增）→ `_globalEventListenerList` 清空（新增）→ `_uiListenerList` 遍历 `OnRemoveListener`（既有，原样保留）。


* 建议修复（一行）：`luaClass.GetViewModel():OnClose()` → `luaClass:GetViewModel():OnClose()`。

* 为何未直接改：属业务逻辑修复而非规范化，遵循「规范化不改业务逻辑」红线，交由你确认后处理（确认后我可立即修）。

## §29.1 UI 监听注册模板同步（生成器对齐 `self:AddUIListener` + `Bind` 风格）

> 用户诉求：生成的 Awake 中 UI 监听注册从
> `AddUIListenerFunction(self.Button, 'Clicked', handler(self, self.OnButtonClicked))`
> 优化为框架风格
> `self:AddUIListener(self.SettingButton, 'Clicked', Bind(self, self.OnButtonClicked))`
> 。

### 改动（注册 4 处，LuaBehaviourInspector）



* `LuaBehaviourInspector.None.cs` L220（Awake 注册）、L749（刷新注册）

* `LuaBehaviourInspector.MVVM.cs` L768（注册）、L1498（刷新注册）

统一由：



```
AddUIListenerFunction(self.{obj}, '{cmd}', handler(self, self.{func}))
```

改为：



```
self:AddUIListener(self.{obj}, '{cmd}', Bind(self, self.{func}))
```

### 关键依据



* `self:AddUIListener`：重构后 `LuaBehaviourSuper:AddUIListener`（L213）/ `ViewSuper:AddUIListener`（L160）的框架注册方法，注册的监听在销毁时自动注销。

* `Bind(obj, method)`**&#x20;与&#x20;**`handler(obj, method)`**&#x20;完全等价**（SystemApis L390/401，Bind 为 handler 别名，返回 `{target, method, func}`），兼容 AddUIListener 自动注销，故注册用 Bind 风格、注销保留 `handler(self, ...)` 可正确匹配。

* 回调用 `Bind(self, self.{func})`（绑定当前运行时实例）而非 `Bind({scriptName}, {scriptName}.{func})`（绑定类表）：生成回调 `function {scriptName}:{func}()` 是实例方法，class 库中类表无实例字段，绑定 self 语义正确。

### 保留项



* 注销行 `OnRemoveListener(self.{obj}, '{cmd}', handler(self, self.{func}))`（None L265/753、MVVM L837/1453）：作为销毁保险保留，`Bind`=handler 等价可匹配。

* MVVM `self:AddBindHandler(self.BVKey.X, handler(self, self.Y))`（L801/1481）：属 MVVM 值绑定，非 UI 控件监听，保留 handler 写法。

### 验证



* `AddUIListenerFunction` 在 Editor 全目录：**0 处** ✓

* 生成 Lua 效果：



```
function cesg:Awake()
    cesg.super.Awake(self)
    self:AddUIListener(self.Button, 'Clicked', Bind(self, self.OnButtonClicked))
end
```



* 改动为 C# 模板替换，无编译风险；**Unity 重新编译后新生成的 Lua 文件生效**（不回溯已有文件）。

## §31 C# ⇄ Lua 通讯方式替换（cmd 统一分发）

### 一、目标
将工程现有 **16 个固定签名强类型委托桥**（LuaEventDelegates.cs + LuaComponent.EventDelegates.cs 的 InitLuaBindings 逐条绑定）整体替换为 **cmd 定义链接 ID 统一分发**（对齐 SDK），Protocol.pb 添加 cmd + 方法即可自动生成链接。

### 二、新通讯方式（三通道）
- **单向事件 → 异步广播**：LuaProtocolRunTime.NotifyLua(cmd, content, state)，Lua 侧 FrameworkProtocolNotify 按 cmd 路由。
- **需立即返回结果 → 同步调用**：LuaProtocolRunTime.SyncCall(cmd, content) 返回 object，Lua 侧 FrameworkProtocolSync 按 cmd 路由并返回（保持同步语义，避免破坏 LuaBehaviour 注入链，非改异步）。
- **请求-响应（网络类预留）**：LuaProtocolRunTime.Request(cmd, content, callback) + ReceiveSuccess/Fail 配对。
